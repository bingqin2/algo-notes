# 33. 搜索旋转排序数组

> [力扣 33](https://leetcode.cn/problems/search-in-rotated-sorted-array/) · 近两年面经里出现在：**字节**
>
> A 层：所有常见解法都要会，闭卷写出，能讲清追问

## 识别信号

**部分有序**的数组里查找：升序数组在某个点被旋转了（`[4,5,6,7,0,1,2]`），要求 O(log n)。关键性质：从任意 mid 切开，**左右两半至少有一半是有序的**。

## 解法一：先判断哪一半有序，再判断目标在不在里面

**思路**：

- `nums[lo] <= nums[mid]`：左半边 [lo, mid] 有序。target 在 [nums[lo], nums[mid]) 里就去左边，否则去右边。
- 否则右半边 [mid, hi] 有序。target 在 (nums[mid], nums[hi]] 里就去右边，否则去左边。

只在**有序的那一半**里判断 target 在不在，因为只有有序的区间才能用两端的值判断范围。

```python
def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:          # 左半边 [lo, mid] 有序
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                              # 右半边 [mid, hi] 有序
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
```

**复杂度**：时间 O(log n)，空间 O(1)。

## 解法二：先找旋转点，再在逻辑有序的数组里二分

**思路**：

1. 用 [153](./lc153) 的方法找最小值的下标 rot：`nums[mid] > nums[hi]` 说明最小值在右边。
2. 把数组看成从 rot 开始的有序数组，逻辑下标 mid 对应真实下标 `(mid + rot) % n`，做普通二分。

```python
def search(nums, target):
    n = len(nums)
    lo, hi = 0, n - 1
    while lo < hi:                         # 先找最小值的下标（旋转点）
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1
        else:
            hi = mid
    rot = lo
    lo, hi = 0, n - 1
    while lo <= hi:                        # 在「逻辑上有序」的数组里二分，下标映射回去
        mid = (lo + hi) // 2
        real = (mid + rot) % n
        if nums[real] == target:
            return real
        if nums[real] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

**复杂度**：时间 O(log n)，空间 O(1)。思路更直观，代码长一点。

## 易错点

- `nums[lo] <= nums[mid]` 写成 `<`：lo == mid（区间只剩一两个元素）时判断错。比如 `[3, 1]` 找 1。
- 判断 target 在有序区间里时边界写错：左半边是 `nums[lo] <= target < nums[mid]`，右半边是 `nums[mid] < target <= nums[hi]`（mid 已经比较过了，不包含）。
- 解法二找最小值时和 nums[lo] 比较：没旋转时会出错，和 nums[hi] 比较才对。

## 面试追问

- **有重复元素（81）？** `nums[lo] == nums[mid] == nums[hi]` 时分不清哪边有序，只能 `lo += 1` 缩小范围，最坏退化成 O(n)，见 [81](./lc81)。
- **找旋转数组的最小值？** 见 [153](./lc153)（无重复）、[154](./lc154)（有重复）。
- **旋转了几次？** 就是最小值的下标。

## Java 版

```java
public int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;
        if (nums[lo] <= nums[mid]) {                  // 左半边有序
            if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                                      // 右半边有序
            if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
```

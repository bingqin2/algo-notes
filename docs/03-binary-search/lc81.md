# 81. 搜索旋转排序数组 II

> [力扣 81](https://leetcode.cn/problems/search-in-rotated-sorted-array-ii/) · 中等 · 来源：题型补强
>
> B 层：掌握最优解法，20 分钟内写出

## 识别信号

旋转排序数组**有重复**元素时查找：思路和 [33](./lc33) 一样，多一种情况：`nums[lo] == nums[mid] == nums[hi]` 时无法判断哪边有序，只能两端各缩一格。

## 最优解法

**思路**：

- 三者相等：`lo += 1, hi −= 1`（它们都不是 target，因为 mid 已经比较过了）。
- `nums[lo] <= nums[mid]`：左半边有序，判断 target 在不在 `[nums[lo], nums[mid])`。
- 否则右半边有序，判断 target 在不在 `(nums[mid], nums[hi]]`。

```python
def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return True
        if nums[lo] == nums[mid] == nums[hi]:   # 分不清哪边有序，两端各缩一格
            lo += 1
            hi -= 1
        elif nums[lo] <= nums[mid]:        # 左半边有序
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                              # 右半边有序
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return False
```

**复杂度**：平均 O(log n)，最坏 O(n)（比如 `[1,1,1,1,1,2,1,1]`）。

## 易错点

- 只判断 `nums[lo] == nums[mid]` 就 `lo += 1`：也可以，但要保证 mid 已经比较过、lo 不是 target。
- 面试常问：为什么最坏是 O(n)？因为大量重复时每次只能排除一个元素，这是信息不足决定的，不是写法问题。

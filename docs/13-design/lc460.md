# 460. LFU 缓存

> [力扣 460](https://leetcode.cn/problems/lfu-cache/) · 近两年面经里出现在：**高频经典**
>
> C 层：认得题型，说得出方法和关键点

## 识别信号

缓存满时淘汰**使用次数最少**的 key，次数相同时淘汰最久没用的；get 和 put 都要 O(1)。是 [146. LRU](./lc146) 的升级版：每个频率一个 LRU 链表。

## 解法一：key→(val,freq) + freq→有序集合 + minFreq

**思路**：三样东西：

- `kv`：key → (值, 频率)。
- `fk`：频率 → 这个频率的所有 key，按最近使用排序（Python 用 `OrderedDict`，Java 用 `LinkedHashSet` 或者自己写双向链表）。
- `minFreq`：当前最小频率，淘汰时直接找到那个桶。

访问一个 key（get 或者更新已有 key 的 put）：从 freq 的桶删掉，加到 freq + 1 的桶末尾；如果 freq 的桶空了且 freq 正是 minFreq，minFreq 加一。插入新 key：满了先淘汰 minFreq 桶里最前面的 key，然后新 key 频率是 1，**minFreq 重置为 1**。

```python
from collections import defaultdict
from collections import OrderedDict

class LFUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.kv = {}                       # key -> [value, freq]
        self.fk = defaultdict(OrderedDict) # freq -> 这个频率的 key，按最近使用排序
        self.min_freq = 0

    def _touch(self, key):                 # 频率 +1，从 f 的桶移到 f+1 的桶
        f = self.kv[key][1]
        del self.fk[f][key]
        if not self.fk[f]:
            del self.fk[f]
            if self.min_freq == f:
                self.min_freq = f + 1
        self.kv[key][1] = f + 1
        self.fk[f + 1][key] = None

    def get(self, key):
        if key not in self.kv:
            return -1
        self._touch(key)
        return self.kv[key][0]

    def put(self, key, value):
        if self.cap == 0:
            return
        if key in self.kv:
            self.kv[key][0] = value
            self._touch(key)
            return
        if len(self.kv) == self.cap:       # 淘汰最小频率桶里最久没用的
            old, _ = self.fk[self.min_freq].popitem(last=False)
            if not self.fk[self.min_freq]:
                del self.fk[self.min_freq]
            del self.kv[old]
        self.kv[key] = [value, 1]
        self.fk[1][key] = None
        self.min_freq = 1                  # 新 key 的频率是 1，一定最小
```

**复杂度**：get、put 都是 O(1)，空间 O(capacity)。

## 易错点

- 为什么 minFreq 只需要 +1：一个 key 频率加一，最小频率最多只会从 f 变到 f + 1，而且只有 f 的桶空了才变。不需要扫描所有频率。
- put 已有的 key 也算一次使用，频率要加一，不能只改值。
- 先淘汰再插入：如果先插入新 key，minFreq 会变成 1，淘汰的就是刚插入的 key。
- capacity 为 0 时 put 直接返回。
- Java 手写版本：每个频率一条双向链表（带哨兵），key → 结点的 HashMap，freq → 链表的 HashMap。

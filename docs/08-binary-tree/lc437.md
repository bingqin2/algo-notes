# 437. 路径总和 III

> [力扣 437](https://leetcode.cn/problems/path-sum-iii/) · 中等 · 来源：Hot 100
>
> B 层：掌握最优解法，20 分钟内写出

## 识别信号

树上求「和为 target 的**向下路径**数」，路径不要求从根开始或在叶子结束：就是 [560. 和为 K 的子数组](../07-hash-prefix-sum/lc560) 搬到树上，只不过「数组」是从根到当前结点的路径，需要**回溯**。

## 最优解法

**思路**：DFS 时维护根到当前结点的前缀和 s，哈希表记录**当前路径上**各前缀和出现的次数。到达结点时，以它结尾的合法路径数是 `count[s − target]`；递归左右子树前把 `count[s]` 加一，返回前减一（离开这个结点后，它不在路径上了）。

```python
from collections import Counter

def pathSum(root, targetSum):
    count = Counter({0: 1})                # 根到当前结点路径上的前缀和

    def dfs(node, s):
        if not node:
            return 0
        s += node.val
        res = count[s - targetSum]
        count[s] += 1
        res += dfs(node.left, s) + dfs(node.right, s)
        count[s] -= 1                      # 回溯：离开这个结点，它的前缀和不再属于当前路径
        return res

    return dfs(root, 0)
```

**复杂度**：时间 O(n)，空间 O(h)（哈希表和递归栈）。

## 易错点

- 忘了回溯 `count[s] −= 1`：兄弟子树会用到不在同一条路径上的前缀和。
- 先 `count[s] += 1` 再查 `count[s − target]`：target = 0 时会把空路径算进去。
- 暴力做法：以每个结点为起点向下 DFS，O(n²)（平衡树 O(n log n)），可以作为第一步说出来。

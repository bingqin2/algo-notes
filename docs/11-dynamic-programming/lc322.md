# 322. 零钱兑换

> [力扣 322](https://leetcode.cn/problems/coin-change/) · 近两年面经里出现在：**美团**
>
> A 层：所有常见解法都要会，闭卷写出，能讲清追问

## 识别信号

凑出一个目标值的**最少**个数，每种物品可以用无限次 → **完全背包**求最小值。也可以看成在「金额」构成的图上找最短路（BFS）。

## 解法一：记忆化搜索

**思路**：f(x) = 凑出金额 x 的最少硬币数 = min(f(x − c) + 1)，对每种硬币 c 尝试一次。

```python
from functools import lru_cache
import math

def coinChange(coins, amount):
    @lru_cache(None)
    def f(x):
        if x == 0: return 0
        best = math.inf
        for c in coins:
            if c <= x: best = min(best, f(x - c) + 1)
        return best
    r = f(amount)
    return -1 if r == math.inf else r
```

**复杂度**：时间 O(amount × k)，k 是硬币种类数；空间 O(amount)。amount 很大时 Python 递归可能超出深度限制。

## 解法二：完全背包 DP（最终写法）

**思路**：dp[x] 从小到大算，dp[x] = min(dp[x − c] + 1)。凑不出的金额用 amount + 1 表示「无穷大」（最多也就用 amount 枚面值为 1 的硬币）。

```python
def coinChange(coins, amount):
    INF = amount + 1
    dp = [0] + [INF] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if c <= x and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    return dp[amount] if dp[amount] != INF else -1
```

**复杂度**：时间 O(amount × k)，空间 O(amount)。

## 解法三：BFS

**思路**：从 0 出发，每加一枚硬币走一步，第一次到达 amount 时走的步数就是最少硬币数。

```python
from collections import deque

def coinChange(coins, amount):
    if amount == 0: return 0
    seen, q, steps = {0}, deque([0]), 0
    while q:
        steps += 1
        for _ in range(len(q)):
            s = q.popleft()
            for c in coins:
                t = s + c
                if t == amount: return steps
                if t < amount and t not in seen:
                    seen.add(t); q.append(t)
    return -1
```

**复杂度**：最坏也是 O(amount × k)，但答案很小时会提前结束。

## 为什么不能用贪心？

「每次拿面值最大的」对 [1, 2, 5] 这样的人民币面值是对的，但不是所有面值都对：coins = [1, 3, 4]，amount = 6，贪心拿 4 + 1 + 1 是 3 枚，最优是 3 + 3，2 枚。面试官很喜欢问这个反例。

## 易错点

- 用 `float('inf')` 或 `Integer.MAX_VALUE` 当无穷大，Java 里 `MAX_VALUE + 1` 会溢出成负数。用 amount + 1 最安全。
- 忘了 amount = 0 时答案是 0。
- 凑不出要返回 −1。

## 面试追问

- **求凑出 amount 的方案数？** 那是 [518 零钱兑换 II](./lc518)：外层循环硬币、内层循环金额，算的是组合数；两层循环反过来算的是排列数。这是背包问题里最容易考的细节。
- **每种硬币只能用一次？** 变成 0-1 背包：金额要**从大到小**遍历，防止同一枚硬币被用两次。
- **要输出用了哪些硬币？** 记录每个 dp[x] 是由哪个 c 转移来的，从 amount 往回找。

## Java 版

```java
public int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);             // amount + 1 当作「凑不出」
    dp[0] = 0;
    for (int x = 1; x <= amount; x++)
        for (int c : coins)
            if (c <= x) dp[x] = Math.min(dp[x], dp[x - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
```
